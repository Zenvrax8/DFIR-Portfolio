# 1. Introduction

Imagine a security guard keeping a notebook at the entrance of a building.

Every time someone enters or leaves, the guard writes down:

- The person's name
- The time
- The door they used
- Whether entry was successful or denied

Weeks later, if an incident occurs, investigators can review the notebook to determine who entered the building, when they entered, and what happened before the incident.

Computer systems maintain similar records.

These records are called **logs**.

Logs are among the most valuable sources of evidence in Digital Forensics and Incident Response because they record the activities of users, applications, devices, and systems over time.

---

# 2. What is a Log?

A **log** is a chronological record of events generated by a computer system, application, or network device.

Logs answer questions such as:

- Who performed an action?
- What action occurred?
- When did it happen?
- Where did it occur?
- Was the action successful?

Logs help investigators reconstruct events and identify suspicious behavior.

---

# 3. Why Are Logs Important?

Logs provide visibility into activities that may no longer be visible elsewhere.

Investigators use logs to:

- Reconstruct attack timelines
- Identify compromised accounts
- Detect failed login attempts
- Trace attacker movement
- Confirm malware execution
- Identify data exfiltration
- Support legal and regulatory investigations

Without logs, many incidents would be difficult—or impossible—to investigate.

---

# 4. How Are Logs Generated?

Whenever a significant event occurs, the operating system, application, or device records it.

Examples include:

- A user logs in.
- A file is deleted.
- A service starts.
- A firewall blocks a connection.
- A web server receives a request.
- An application crashes.

These events are written to log files or centralized logging systems.

---

Different systems generate different types of logs.

Examples:

- User logins

- Service activity
- Security events
- Software installation

---

### Application Logs

Examples:

---

### Network Logs

Examples:

- Firewall logs

---

### Security Logs

Examples:

- Antivirus detections
- EDR alerts
- IDS/IPS events
- SIEM alerts
- Authentication failures

Each log source provides a different perspective on an incident.

---

# 6. Anatomy of a Log Entry

Although formats vary, most log entries contain similar fields.

Example:

```text
2026-07-18 14:32:18
HOST: WS-101
USER: jsmith
EVENT: Successful Login
SOURCE IP: 192.168.10.25
STATUS: Success
```

Common fields include:

- Timestamp
- Hostname
- Username
- Event type
- Source IP
- Destination IP
- Process name
- Event ID
- Status

Understanding these fields is the first step in effective log analysis.

---

# 7. Correlating Logs

A single log entry rarely explains an incident.

Investigators compare logs from multiple sources.

Example:

| Source | Event |
|--------|-------|
| Email Logs | Phishing email delivered |
| Windows Security Log | User logged in |
| Firewall Log | Connection to suspicious IP |
| EDR | Malware detected |
| VPN Log | Remote login from unusual location |

Viewed together, these logs reveal the sequence of the attack.

This process is known as **log correlation**.

---

# 8. Challenges in Log Analysis

Logs are valuable, but they also present challenges.

Investigators may encounter:

- Large volumes of data
- Missing logs
- Inconsistent timestamps
- Different log formats
- Log retention limits
- Clock synchronization issues
- False positives
- Log tampering

Understanding these limitations helps investigators avoid incorrect conclusions.

---

# 9. Real-World Example

A company's SIEM generates an alert for multiple failed login attempts.

Investigators review:

- Windows Security Logs
- VPN Logs
- Firewall Logs
- Active Directory logs
- EDR telemetry

The investigation reveals:

- Hundreds of failed VPN logins.
- One successful login from an unfamiliar country.
- Creation of a new administrator account.
- PowerShell execution shortly afterward.
- Outbound connections to a known malicious IP address.

Correlating logs from multiple systems allows investigators to reconstruct the intrusion.

---

# 10. Common Mistakes

New investigators often:

- Analyze only one log source.
- Ignore timestamp differences.
- Fail to verify time zones.
- Assume missing logs mean no activity occurred.
- Overlook log retention policies.
- Focus only on alerts instead of reviewing surrounding events.

Effective investigations require context.

---

# 11. Best Practices

Professional investigators should:

- Collect logs from multiple systems.
- Normalize timestamps before analysis.
- Correlate logs from different sources.
- Preserve original log files.
- Verify log integrity where possible.
- Document findings and assumptions.
- Review events before and after suspicious activity.

Logs should always be interpreted within the broader context of the investigation.

---

# Remember This

- Logs are chronological records of events.
- Every log entry answers part of the investigative story.
- No single log source provides the complete picture.
- Log correlation is essential for reconstructing incidents.
- Time synchronization is critical for accurate analysis.
- Context is just as important as the event itself.

---

# Key Terms

| Term | Meaning |
|------|---------|
| Log | A chronological record of system or application events |
| Log Correlation | Combining logs from multiple sources to reconstruct activity |
| Event | A recorded action or occurrence |
| Event ID | A numeric identifier representing a specific type of event |
| SIEM | A platform that collects, correlates, and analyzes logs from multiple sources |
| Log Retention | The length of time logs are stored before being overwritten or deleted |
