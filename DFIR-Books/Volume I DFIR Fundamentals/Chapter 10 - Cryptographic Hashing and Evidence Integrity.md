# 1. Introduction

Imagine you have an important legal document.

Before placing it into a secure locker, you record every word on the first page.

Months later, when you retrieve the document, you compare it with your record.

If even one letter has changed, you immediately know the document has been modified.

Digital investigators use a similar concept.

Instead of recording every byte manually, they calculate a unique digital fingerprint for a file.

This fingerprint is called a **cryptographic hash**.

If the evidence changes—even by a single bit—the hash value changes.

This allows investigators to verify that digital evidence has remained unchanged throughout the investigation.

---

# 2. What is a Cryptographic Hash?

A **cryptographic hash** is a fixed-length value generated by applying a mathematical hash function to digital data.

No matter whether the input is:

- A text file
- A memory dump
- A hard drive
- An image
- A video

The result is a unique hash value.

Think of a hash as a digital fingerprint.

Just as no two people have the same fingerprints, two different files should not produce the same hash under normal circumstances.

---

# 3. Why is Hashing Important?

Digital evidence must remain unchanged.

Investigators use cryptographic hashes to verify that:

- Evidence has not been modified.
- Forensic images are accurate copies.
- Files remain unchanged during storage.
- Evidence transferred between investigators is intact.
- Analysis is performed on authentic evidence.

Without hashing, investigators cannot confidently prove that evidence has remained unaltered.

---

# 4. How Hashing Works

A hash function accepts digital data as input and produces a fixed-length output.

```text
Digital Evidence
        │
        ▼
Hash Function
        │
        ▼
Hash Value
```

For example:

```text
File → SHA-256 → 3F9B1A7E...
```

If a single bit changes, the resulting hash value will be completely different.

---

# 5. Characteristics of a Good Cryptographic Hash Function

A cryptographic hash function should have the following properties.

### Deterministic

The same input always produces the same output.

---

### Fast to Compute

Hash values should be generated efficiently, even for large files.

---

### Fixed-Length Output

Regardless of input size, the output length remains constant.

For example:

- SHA-256 always produces a 256-bit hash.

---

### Avalanche Effect

A tiny change in the input should produce a completely different hash.

Changing one character in a file results in a drastically different hash value.

---

### Collision Resistance

It should be computationally infeasible to find two different inputs that produce the same hash.

This property is essential for maintaining trust in digital evidence.

---

# 6. Common Hash Algorithms

Several algorithms have been used in digital forensics.

| Algorithm | Status |
|-----------|--------|
| MD5 | Legacy; no longer recommended for security-sensitive purposes |
| SHA-1 | Legacy; collision weaknesses are known |
| SHA-256 | Widely recommended for forensic integrity verification |
| SHA-512 | Stronger variant of the SHA-2 family |

Modern forensic investigations typically rely on SHA-256 or SHA-512.

---

# 7. Hashing vs Encryption

These concepts are often confused.

| Hashing | Encryption |
|----------|------------|
| Verifies integrity | Protects confidentiality |
| One-way process | Two-way process |
| Cannot be reversed | Can be reversed with the correct key |
| Produces a hash value | Produces encrypted data |

Hashing answers:

> **"Has this data changed?"**

Encryption answers:

> **"How can this data be kept confidential?"**

---

# 8. Hash Verification During an Investigation

A typical workflow is:

```text
Original Drive
      │
Calculate SHA-256
      │
      ▼
Hash Value
      │
Create Forensic Image
      │
Calculate SHA-256 Again
      │
      ▼
Compare Both Hashes
      │
      ▼
Match?
      │
 ┌────┴────┐
 │         │
Yes       No
 │         │
Evidence  Investigation Required
Verified
```

If both hash values match, investigators have strong evidence that the forensic image accurately represents the original.

---

# 9. Real-World Example

A DFIR analyst acquires a 1 TB SSD from a compromised workstation.

Before imaging the drive:

- The analyst calculates the SHA-256 hash of the original SSD.

After imaging:

- The analyst calculates the SHA-256 hash of the forensic image.

The two values match exactly.

Months later, another investigator verifies the image by recalculating its hash.

The result is identical.

This demonstrates that the evidence has remained unchanged since acquisition.

---

# 10. Common Mistakes

Investigators should avoid:

- Forgetting to calculate hash values.
- Using weak or outdated algorithms without justification.
- Recording hash values incorrectly.
- Failing to verify forensic images.
- Assuming evidence integrity without verification.

Integrity should always be demonstrated—not assumed.

---

# 11. Best Practices

Professional investigators should:

- Calculate hash values immediately after acquisition.
- Verify forensic images before analysis.
- Use SHA-256 or stronger algorithms whenever appropriate.
- Record hash values in investigation documentation.
- Recalculate hashes after evidence transfers when necessary.
- Preserve the original evidence securely.

Hash values should accompany digital evidence throughout its lifecycle.

---

# Remember This

- A hash is a **digital fingerprint** of data.
- If even one bit changes, the hash changes.
- Hashing verifies **integrity**, not confidentiality.
- SHA-256 is widely used in modern DFIR.
- Matching hash values demonstrate that evidence has not been altered.
- Always verify evidence before beginning analysis.
